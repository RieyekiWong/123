# Stillwater 4.13：主线证据核对升级

基线为 4.12.1 / `392334a`。这是现有新版上的增量修改。旧版、微信与 AI 后端、论坛原帖和评论、普通广告、W3-02 广告，以及 B-3 电路算法不在本轮重写范围内。

实施前的依赖检查和分步计划保存在 [实施计划](V2_13-INVESTIGATION-PLAN.zh-CN.md)。本报告含完整答案，属于开发资料，玩家页面和导航不链接本报告。`npm run build` 的 `dist/` 不包含 `docs/`；GitHub Pages 继续使用仓库原有发布配置。

## 实际界面和引导

- 员工导航新增“证据核对台”，工作笔记保留原有原件入口及历史结局，并增加核对台入口。
- 核对台列出已发现资料，显示标题、出处、日期、记录编号与原始字段。两份原件可以对照、移出、重选；字段标记由玩家自己操作，不自动标红差异。
- “当前调查”只突出 1–3 个方向，不放传统进度条。未开放的人员核对使用通用名称，不提前露出 Mara。
- 笔记分别显示已核对、正在调查、尚未开放。已找到的事实与已提交通过的推断分开保存。
- 首次样本登记是真实操作练习，不是自动播放教学；离开后可以接着做。
- 所有原件可重开；维修附件也会立即出现在来源列表。上次调查位置保留原始查询参数，经过笔记页不会覆盖成笔记页本身。
- 新增核对可用点击、键盘和手机完成。记录性质使用下拉选择，不要求拖拽。
- 三级提示逐级主动打开并存档；错误次数和停留时间不会自动展开提示。预订、目录、维修、修订、监控、接线、广告来源、黑暗辨门、拼片和新增证据核对均有对应帮助。
- 错误指出缺少的原件、无关的引用或判断问题；不删资料、不取消早先的正确核对、不清空已确认的时间顺序。

## 完整答案与验证规则（开发剧透）

| 核对 | 必须引用的原件 ID | 正确提交 | 不足以完成的操作 |
| --- | --- | --- | --- |
| 样本登记 | `sample`, `booking` | `match=same`；两份原件还须分别打开并放入对照栏 | 只填“同一笔记录”、只引用、只打开 |
| 空间用途 | `inventory`, `position` | `use=service` | 获得 C3、查看 C5、只选用途都不够 |
| 夜审 | `key`, `housekeeping`, `transfer`, `draft-audit` | 顺序 `message → housekeeping → transfer → draft`；巡查 `observation`，移交 `system`，入住判断 `claim`；`assessment=insufficient` | 只按时间排序；认定“没人曾进入”；只读附件 |
| 身份 | `personnel`, `revision`, `queue`, `attendance` | `role=reviewer`；`attendance=insufficient` | 仅勾出修订差异，或把自动排班当成到岗证明 |
| ROOM | `inventory`, `position`, `footage` | `finding=unsupported` | 只点 ROOM；仅引用登记卡；只把录像加入资料库 |
| GUEST | `booking`, `key`, `housekeeping`, `transfer` | `finding=unverified` | 把分配、钥匙套或系统移交直接当作入住证明 |
| EMPLOYEE | `personnel`, `revision`, `queue`, `attendance` | `finding=unverified` | 把工作编号当作到岗，或据修订把原处理人改成住客 |

所有引用须已实际发现；不能引用未开放资料或把判断卡当成原件。提交多余的无关资料也不会通过，不能用“把所有文件全选”代替挑选依据。最后三类仅在走廊、拼片与终端均实际到达后提交。

空间核对保存 `317 / POSITION TYPE / SERVICE HOLDING`；时间核对保存 `R-4829 / OCCUPANCY NOT VERIFIED`；身份核对保存 `E-014 / ORIGINAL ROLE: REVIEWER` 与 `TEMP-015 / ATTENDANCE UNVERIFIED`。

“目前证据不足”不等于证明从未有人进入。ROOM 的结果是不支持当前归类，不宣称未知位置绝不可能有其他用途。到岗索引只说明本次保留资料中没有相应签收，不凭空建立未到岗的绝对事实。

修订差异仍需原有 `owner / location / status` 三项，`reference / assignment` 未变。差异通过获得 C7，但 C8 新增身份复核条件，队列提前可查，避免出现循环锁。

### 最终处理及原结局

- `force`：明确记录所强制选择的 `ROOM / GUEST / EMPLOYEE`，接回 `auto-close`。
- `auto`：记录接受系统自动结案，接回 `auto-close`。与强制分类在存档中有不同处理方式。
- `retain`：保留未核实，返回原 B-3 交接。玩家仍可走 `unverified`；也可按原条件锁定备份后取得 `released`。
- `released` 没有放宽：真实连通、隔离、手动、保存、缓存帧、维修通道、完成纯黑章节和明确锁定原件缺一不可。
- 原 B-3 中允许提前结案或不签字离开的两个分支继续保留。三个最终分类全部核对，约束的是新终端的最终处理，不删除原有提前离开路径。

## 存档迁移

继续使用 `stillwater-case:v2`、schema 2，新增 `desk.schema=1`。没有改主存档键，没有清除聊天、广告或旧版存档。

- 新玩家：来源、草稿、比较栏、字段标记、已提交结果、三级提示、时间顺序、性质分类和录像快照分别保存。
- 旧存档没有 `desk` 时：按原有 C5、已完成夜审、C7 等事实保留相应历史完成记录，明确标注 `legacy`，不要求重解已经完成的旧谜题。
- 旧 C3/C4 保留；新 C4 在 C3 之前发现也能恢复原发现顺序。
- 已到 B-3、已进入黑色空间或已有结局的记录继续可用。旧分类终端已经检查的类别带兼容标记保留；未检查类别可继续新复核。
- 新存档的完成结果按真实判断和来源验证，不把任意布尔值当成解谜结果。最终类别的来源也与主核对结果复核。
- 已提交时间核对保存提交时的分类，后来的草稿修改不会污染确认结果；反复刷新仍保留。
- 录像保存当时的视角与场景状态，不保存大量图片数据。之后转动摄像头或改接线路，不会修改已经保留的这份来源。

## 三项引导检查

| 谜题 | 玩家知道当前要做什么 | 信息能找到、重开 | 需要自己推理 |
| --- | --- | --- | --- |
| 样本登记 | 短练习说明与“编号对应” | 只展示两份已知资料，分别可返回原页 | 判断编号是否对应并实际引用 |
| 空间 | 当前目标“确认 317 的原始用途” | 目录、平面图、登记卡有双向入口 | 区域编号与可订客房不是一回事，须引用两份资料 |
| 时间 | “先确认顺序，再核对记录各自能证明什么” | 四份卡均附原页入口；漏看留言有明确反馈 | 分清观察、系统处理、入住判断及证据不足 |
| 身份 | 当前目标“Mara 与当前排班” | 原档、修订、当前队列、到岗索引可重查 | 不把字段改名或自动派工当作身份与到岗证明 |
| 监控与接线 | 原空间、设备状态与检修说明，另有主动提示 | 机位、走廊、B-3 均保持原入口 | 仍需看地标、接真实连续线路，不以打开说明代替 |
| 最终类别 | 三个类别各有明确核对问题 | 分类窗口直接查看原件；录像遗漏可回 B-3 补存 | 每项都要判断和来源，三次点击不会通过 |
