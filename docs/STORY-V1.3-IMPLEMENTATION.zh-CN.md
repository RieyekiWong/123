# 《没有登记的人》V1.3：故事与系统改造记录

依据：完整阅读用户上传的 306 行 V1.3 小说；V1.3 为核心故事，V1.2 补充不冲突的人物生活。第 1–7 节保留改造前的审查与计划，第 8 节起记录 4.19.0 的实际实现、素材与验收。发布状态另记，不把候选模块或图片规划当成成品。

## 1. 改造前的状态及冲突（审查记录）

- 当前 Git 基线仍为 4.17.0 / `048d61a`。本地 4.18.0 第一阶段已完成新微信开场、版本化私聊、旧聊天与七张素材，131 项单元测试、28 项聊天浏览器测试通过。尚未发布。
- 三个 `case-story-v12-*` 文件是未接入的第二阶段候选模块；此前没有被 HTML 或发行清单引用，不代表酒店主线已经换完。停止按 V1.2 继续扩展它们，改按本稿整合。
- 线上旧路线仍缺 Nora、Ethan、Helen 签字和 Ruth 的独立来源；单纯改几句 Mara 台词不能补足根源。Mara 的 E-014 不能分配给 Nora，E. Vale 也不能改名为 Nora。
- 旧住客是 E. Vale / 318；317 是员工服务暂存区；03:17 的系统移交不等于入住；Mara 在 03:24 保留 UNVERIFIED。四件事继续成立。
- Nora 27 岁、2006 夜班前台及档案整理，确实到岗。2007 的“已离职”是被签改的记录，不是实际离开的证明。玩家不能通过否认 Nora 是员工来通关。
- 最早空间异常出现在 2006。Continuity 后来传播和混合异常，不能写成软件从零制造鬼魂。NULL 以 Nora 残余为中心，不等于完整 Nora，也不等于王楚人；新账号是合成身份，不等于旧号复活。
- 最后旧微信为 2023-10-17 18:12。相机文件 18:26；展示亭日志证明其后还停留过一段时间，但日志只在 RELEASED 恢复后可见，不编造小说未给出的精确分钟。
- 新稿假头像来自 2022 校园照，不再来自咖啡店旧头像。已有咖啡店头像保留为普通生活照；新增校园母图和派生新头像，旧文件不覆盖。
- 最后相机照需有被覆盖的海报／指示牌边缘及展示亭语境。已有普通门照不能被直接宣称具有这些细节；须制作可追溯的完整原图与显示版本。
- 小说把 Ruth 拼成 Keene，用户本次要求写 Keane。对外统一按本次要求 `Ruth Keane / 露丝·基恩`。没有设置 Ruth 姓名输入关卡，不把拼写差异设计成谜题。
- 弟弟的生活动机按用户最新要求为生日照片；不把毕业照、生日照写成两个必须追查的日期。
- 王楚人讨厌 `final_final_2` 式命名，假账号却声称这是他的习惯：保留为有旧记录可对照的具体错误，不让旁白说“因为像 AI 所以是假的”。地图玩笑只证明材料复用，不证明本人在线。

## 2. 一条主线，从微信到三个结局

1. 普通群聊提起照片；旧会话、生活照与 GG 的共同经历让玩家认识朋友。家人和学校存在于可选资料中，不成为第二条任务。
2. GG 私聊找到重新可用的网站，真实论坛卡片进入原帖。论坛、招聘、酒店仍各自像普通网站。
3. 工作样本给出旧站来源，自动进入正常酒店。当前目标明确为查找王楚人的姓名记录。
4. 姓名索引显示 2006 / 317；GG 主动来消息。玩家比较 R-4829、目录和区域卡，保存有来源支持的判断。
5. 正确核对被网站反向同步。日记、课程归档和旧聊解释 2023 行程；玩家区分真实文字与入住补写。
6. 缓存恢复后出现好友申请。接受与忽略都有资料可查；校园旧照、派生头像与消息出处支持下一次调查。
7. 沿王楚人的课程资料找到 Ruth 留存的 Nora 员工资料：排班、工时、Ethan 询问信、2007 签改单、Mara 留稿。人物生活与责任逐渐清楚。
8. 来源核对后 Helen 发来邮件，先承认修订不是原件，再面对自己签字的后果。系统生成当前处理责任，酒店变化，进入监控。
9. 保留三机位地标与 317 走廊操作。进入 B-3，按真实六接头规则恢复线路、隔离、MANUAL、保存，核对 W3-02。
10. 区分 2006 原始五秒、2026 混合预览、2023 本地相机文件。NULL 的错帧和两种来源的台词揭示身份被拼接。直接进入黑空间。
11. 保留选门、观察和拼片。最终三类核对拒绝把不同人的证据强塞进一个身份，然后由玩家明确选择处理方式。
12. AUTO CLOSE 接受合成记录；UNVERIFIED 不伪造答案但未分离全部原件；RELEASED 分离并锁定来源，恢复相机边缘与展示亭日志。旧微信无新增回复，三个结局均明确结束。

## 6. NULL 出场与信息后果

1. 早期坏链／损坏边角：只有残片与“没写完”，不提前给完整 Nora 背景。
2. 日记来源恢复／GF-01：普通句接入住模板；恢复真实照片和来源，带来好友申请。
3. 玩家正确结果被同步／GF-02：保留原件不被删除，显示副本试图把 Nora 的工作身份或未知状态覆盖；新的目标是查签改单和原始录像。
4. 中后期损坏资料：“我那天确实上班了”“你不能把我写成他”“可是我用他的名字，门才肯开”；每句分别有工时、合并字段、确认诉求可追查。
5. B-3／GF-03：保留已确认的错帧脸；Nora 的工作句与王楚人的地图玩笑串到一起。原始和混合版本分开标，不让怪物代替事实来源。
6. 终章：“所以我不是他”“那你也别把我删了”；承认差别不等于获得原谅。玩家保留各自记录，不把 Nora 换成另一名住客。

非关键环境异常继续绑定观察操作。无固定频率强行弹脸；减少动态、跳过鬼脸、静音均保留相同剧情和证据。

## 7. 分阶段实施与测试标准

A：统一 V1.3 事实、复用微信开场、补校园与 Nora 素材；旧号无新消息，AI 服务不重写。

B：接入新的来源流程、Nora 责任链、固定邮件与六处转场；旧 C1–C9 原档保留，移除新流程的旧必做门槛，不伪造全收集。

C：连接 CCTV、B-3、混合预览和黑空间；区分可读录像与完整分源／锁原件。UNVERIFIED 不能要求玩家故意接坏电路；RELEASED 的奖励必须来自真正恢复的文件边缘及日志。

D：新档实际从微信到三个结局、错误来源、忽略申请、关闭广告、长文关闭后转场、转场中刷新、旧 B-3／黑空间／结局存档、中英文、手机、键盘、音效与无障碍。不得靠手动改 hash 或注入完成标志冒充完整通关。

旧档继续使用 `stillwater-case:v2`；聊天继续 `stillwater-chat:v1`，保留既有脚本键与真实输入。新剧情采用独立版本和事件键。旧深层存档不锁回前章，不因为缺 Nora 字段抹去结局。
