# Stillwater Hotel 2.0：《第二个自己》——Stage 0 审查包

审查日期：2026-11-05。状态：**审查和设计已完成，2.0 运行代码尚未实施。** 本目录包含剧情答案和开发规则，不进入玩家网站或 `dist/`。

## 依据与范围

本轮以用户上传的《Stillwater_2_0_Master_Blueprint (1).md》全文为主要依据，参考《Stillwater_2_0_Reference_Index.md》。文档中的实施建议经过现有代码核对后转为下列计划；不会把附件里描述的功能当作已经存在。

用户随后补充的要求优先于蓝图 §11.1 的“只保留少量正常广告”：**保留现有喜欢的弹窗广告，在不吓人的场景才允许弹出。** 25 组普通广告、广告夹和取消推送设置保留；旧 W3-02 必做谜题退出 2.0 主线，原版继续保留它的全部规则。

本次只读审查运行代码、建立备份、运行现有测试并新增开发文档；没有生成图片、音频或视频，没有改写剧情页面，没有修改 Worker 或部署网站。

## 先看这些结论

1. 仓库真正运行的是 **4.19.0 / 故事 V1.3**。`v2-*` 测试名、`V2_FILES` 和 `stillwater-case:v2` 指的是现有技术版本，不能拿来代表这次的故事 2.0。
2. 微信不是一个可随意替换的开场页。聊天有独立存档、固定事件入口、AI 协议、房间限制、输入节奏、通知和浏览器 DOM 缓存。2.0 复用这些能力，仅增加剧情版本适配和存储参数。
3. 现有新剧情叠加在 C1–C9、旧夜班及纯黑分类模型上。继续往这些条件里加判断，会把被删去的任务悄悄带回来。2.0 使用独立剧情状态和路由，不伪造 C9、旧结局或旧核对结果来解锁新页面。
4. B-3 的旋转与连通规则可以保留。已穷举 4,096 种朝向、共 16,384 种朝向/隔离/模式组合，得到一组有效状态。重制的是信号含义和剧情后果，不是接头玩法。
5. 2.0 的主要矛盾是 **酒店 2007 年停业，2026 年修复页却声称王楚人在 2023 年入住并仍在馆内**。现有“王楚人 2006 年入住”的索引不能混入新故事。
6. NULL 是多个受困意识和教义归档共同形成的冲突体。Nora 是其中一个仍在试图保护他人的人；不能把她本人等同于鬼脸。
7. 位体教先是一家有历史、工作人员和普通访客的公共机构。它的首页不会开场变成恐怖机关；问题从被改写的具体档案中显露。
8. 关卡完成顺序统一为：**保存结果 → 让玩家看懂变化 → 触发固定剧情 → 进入下一处**。长文、证词和聊天阅读期间不抢走页面。
