# 4.15：黑色终章与微信应用切换

## 界面与状态恢复设计

普通消息是浏览器之外的通知层：电脑右上角，手机顶部。它不会自动跳转或改动谜题。通知关闭或超时后，消息和未读状态仍由原微信模型保存。发消息、AI 请求和主线论坛分享继续走原路径，通知内容不能决定游戏进度。

通知的入口携带固定的联系人 ID。微信读取该 ID 打开对应聊天；聊天顶部增加返回浏览器的标签，手机显示小型“返回 Stillwater Hotel”入口。

同一文档内切换时，浏览器原有 DOM 保存在 DocumentFragment 中，返回时复用原节点。刷新后的恢复使用单独的 `stillwater-browser:v1`：只存本游戏的路由、滚动、有限的表单值和焦点；不存聊天输入，不存 HTML，不发送给服务端。恢复只设置控件，不触发谜题提交。原来的 case、chat、广告存档键及 schema 不变。

## 普通消息与关键异常

普通问候复用现有角色写好的日常消息，分别进入各自私聊。首次在前半段浏览 45–75 秒后可能出现，之后间隔 90–150 秒；每个角色只问候一次。后台标签、弹窗、微信和第二阶段不计入这段等待。已发送的问候由原聊天记忆去重。预先发送的 AI 回复仍可正常到达，但新通知不会主动调用 AI。

`stillwater-messenger:v1` 保存问候计时与剧情异常是否看过。新玩家首次读到 C9、第一阶段仍正常时，七位联系人轮番刷出“不要再调查”，随后出现变色的临时微信窗口；整个事件六秒结束。它是独立覆盖层，不把假消息写入真实聊天、记忆、未读数或 AI 上下文。结束后移除覆盖层、释放原页面；刷新或离开会立即清理，Escape 或关闭按钮也可退出。已到 C9 的旧存档和后半段存档不会被强制补播。确认重新开始会清理新增的应用切换记录。选择减少动态效果或跳过惊吓时，改为一次显示七条静态警告，仍保留六秒剧情，不持续刷屏或染色。

## 终章

最终分类仍校验原来的资料与判断，但改成单列黑色终端。每类只显示一个短问题、4–5 条相关原件和简短判断；旧草稿里的额外引用仍可取消。原件以折叠的只读记录重看，完整核对台仍保留。三种最终处理与结局条件未改。

获确认的闪屏效果接到真正的黑色解谜页面，不播放演示 MP4。首段等待 12–18 秒，之后等待 18–28 秒；每次干扰约 0.88 秒，每两次随机安排一次鬼脸，鬼脸在噪波中出现约 0.29 秒。嘶声使用既有音效总线与音量，不创建新的 AudioContext。静音、跳过故障、减少动态效果、后台、设置和离开章节均可清理相关表现；既有剧情突脸优先，干扰不接管输入，也不推进存档。
