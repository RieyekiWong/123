# 4.13 文案：继续沿用七条要求

本轮只整理受主线升级影响的文案。4.11 已完成的全站整理继续保留，见 [上一轮完整对照](V2_11-COPY-REVIEW.zh-CN.md)。微信聊天、论坛原帖和评论、普通广告不再重写。

七条要求用于改善真实表达，不是每句话都套七种修辞。酒店照常介绍客房与服务；员工系统用短标签和具体的审核反馈；Mara 的备注保留口语和犹豫；终章仍保留系统术语。没有编造现实统计、权威背书或新案件事实。

## 主要改动对照

| 位置 | 原表达 / 原展示 | 本轮表达 / 本轮展示 | 原因 |
| --- | --- | --- | --- |
| 住客留言附件 | “……请先查看当天的楼层图。” | “……附件留有当天的楼层资料。” | 像前台留存附件，不用命令句安排玩家下一步 |
| 客房巡查 | “318 空置，床品未使用。这里只记了这间房的情况。” | “318 空置，床品未使用。” | 巡查只记观察，不替玩家解释证据边界 |
| 巡查英文 | “This record does not establish occupancy elsewhere.” | 删除这段说明，保留房间空置与床品状态 | 将“能否证明”留给玩家核对 |
| 维修英文 | “This action did not verify actual guest occupancy.” | “The occupancy field is blank.” | 写清字段状态，而不是直接给推理结论 |
| 当晚备注英文 | “no confirmed guest is evidenced …” | “I cannot confirm whether anyone stayed … Leave the record unverified.” | 更像当班人员在留备注，不像案件摘要 |
| 修订英文说明 | 直接指出原预订编号未变、原处理人被改为住客 | 要求逐行比较原稿与修订；提供原住客姓名供核查 | 留下可靠事实，移除替玩家总结的答案 |
| 修订漏选帮助 | 直接列出人员、区域用途、状态三栏 | “仍有改动未标记。请把每一行的两份内容读完。” | 不用帮助列表代替观察 |
| 修订后说明 | “对比结果已保存，附有同日通知。” | “字段对照已保存。人员资料中保留着原档案和当前队列。” | 说明当前已完成什么，指向可调查来源；不自动写下身份结论 |
| 夜审页 | 长句一次说明排序与结论提交 | “先确认时间顺序，再核对这些记录各自能证明什么。” | 分开操作与判断，减少一次阅读负担 |
| 最终汇总 | 再选六项说法中的三项 | “提交已完成的来源核对，原始资料会继续保留。” | 避免重复考试式勾选，保持内部审核身份 |
| 类别终端 | 点击即显示“与原件不符”及现成解释 | “核对这段影像的归类依据。”；点击只打开对应核对 | 让玩家先观察、引用，再判断 |
| 未开放笔记 | 提前列 Mara 的正式核对标题 | “人员资料核对 / 尚未开放” | 状态清楚，人物信息不提前泄露 |
| 完成结果标题 | “已确认的核对” | “已保存的核对结果” | 避免别扭的名词堆叠 |

## 新文案的场景规则

- 操作标签直接用“查看”“加入对照”“移出对照”“引用的原始资料”“提交来源核对”。不把一个简单动作包装成长句。
- 缺少资料时写“还缺少一份原始资料：……”；不是笼统的“错误”，也不夸张地威胁玩家。
- 选错入住结论时，分别说明“缺少入住依据”与“无法确认不等于证明从未有人进入”。两种错误不会混为一谈。
- 自动排班只证明系统产生了工作安排。到岗索引明确限定检索范围为保留的资料，不扩大成“此人绝对没来过”。
- 录像所见、系统叠字、玩家判断分开。没有给原来无法辨认的人影安排一个新的确定身份。
- 提示的三级顺序是观察方向、相关资料、操作方法。只在主动索取时展开，不靠长篇旁白推进。
- 中英文围绕同一事实分别表达。英文不额外泄露答案，也不要求所有人说客服用语。

新增的完整来源、选项、反馈和提示分别在 `case-data.js`、`case-evidence.js`。逐项提取的双语新增/移除文案另存 `v2.13/copy-review.json`；它是源码文本清单，不能当作所有动态状态的实际渲染记录。
