## NULL 用的哪张脸

继续使用玩家已确认的 `assets/previews/v415-signal/apparition.png`。原文件未改，没有替换成附件带 NULL 字样的概念脸。

- 早期：旧聊天照片角落的淡矩形，没有正常网页上的突然大脸。
- GF-01：恢复 2023 快照，缩略图中的半脸。
- GF-02：修订责任预览，较完整的错位脸。
- GF-03：原始 03:17 线路与帧恢复后的近景；标记为无身份、无机位索引，绝不声称 2006 录像拍到 2023 的王楚人。
- 黑色章节：保留已认可的噪波与丝声，间歇演出只露局部残影。三次主要演出各有保存 ID，刷新不会再播。

仍是约 0.88 秒信号干扰，脸混在中间约 0.29 秒。沿用原噪波绘制和效果音总线；不新增尖叫、不创建逐次 AudioContext、不拦截点击或键盘。减少动态效果、跳过鬼脸、静音分别生效。六处 NULL 台词保存在原件、记录或黑空间中，关闭特效不会漏线索。

手动演出预载已修复：预载期间先保留演出目标，避免普通页面同步把首次演出取消。目标离开、隐藏标签和偏好改变仍可取消效果。

## 新谜题答案与本地规则

### P1

沿用 C1/C2 原件登记教学。当前招聘样本和 2006 酒店原件属于不同来源，不证明 2026 仍在营业。不会调用 AI 判题。

### P2：姓名索引

- 前置：C5 和原空间用途来源核对已完成。
- 必须查看并引用：`index`、`booking`、`inventory`、`position`。
- 必须在姓名索引标记：`name`、`year`、`position`、`revision`。
- 必须实际把 `index` 与 `position` 放入对照。
- 判断：`stay=insufficient`。不能用入住记录不足推出人不存在。
- 成功只生成显示字段更新，不改 E. Vale 或原始 318。

### P3：文字出处

- 前置：P2；恢复 2023 快照。
- 引用：`notebook`、`guestlog`、`draft`、`forum2023`。
- `stay`、`map` 属于独立 2023 来源；`normal`、`check` 属于 2026 模板；`tomorrow` 留作未知。
- 四项判断：`handwritten=insufficient`、`visit=supported`、`occupancy=insufficient`、`author=insufficient`。
- 不因某句有删除线便当作真实；不把同照片的转发当成独立证据。

### P4 / SP01：来源路径

- 引用并查看：`oldchat`、`forum2023`、`sync`、`echo`。
- 实际比较：`sync` 和 `echo`。
- `map=public`；`quote=forum2023`；`upstream=system`；`identity=insufficient`。
- 论坛保留 GG 把地图拿反的原话；“不是来住店”的可验证旧出处在 2023 回复；新的 317 字段由系统先生成，再由账号复述。
- 接受与忽略使用同一证据规则。忽略时明确显示公开留言转录，不能假装获取了未接受账号的私人消息。

### SP02：叠片

使用两张匹配构图的独立图片。保存两个地标 `frame`、`lamp`；偏移 X/Y 误差各不超过 1%，缩放距 100% 不超过 1%；不一致部位为 `plaque`。

透明度不是通关条件。错误移动不会清除已经保留的观察；保留记录存有自己的几何快照，刷新不会因后续查看角度变化而丢完成状态。

### P5：因果链

附上 `booking`、`key`、`housekeeping`、`transfer`、`mara`、`revision`、`index`。

| 连接 | 性质 | 对应来源 |
| --- | --- | --- |
| 318 预订 → 钥匙套 317 | observation | key |
| 钥匙套 → 02:50 床品未用 | observation | housekeeping |
| 空置 → 03:17 系统移交 | system | transfer |
| 移交 → 03:24 Mara 不予确认 | observation | mara |
| Mara 原备注 → 2007 身份、位置、状态改写 | revision | revision |
| 2023 材料 → 显示为 2006 已入住 | inference | index |

六个连接逐项引用，不能仅按日期排序。核对完成后还要主动选择签字预览的处理方式，才允许新档同步进入监控。预览不替代真正的夜班最终处理。

### P6：影像边界

保留原三分类的准确来源与判断。之后必须引用 `footage`、`notebook`、`index`，选择 `finding=unverified`。

缺少录像来源或影像尚未恢复，不能从核对台提前取得它。缺少身份依据，不等于证明从未有人进入。三份资料分别能证明的内容不同。

## 存档和原玩法

- 仍是 `stillwater-case:v2` / schema 2，新增 `story` 子对象。缺少它的既有存档进入兼容路径；C1–C9、B-3、黑空间及已取得的结局不被锁回前面。重新开始才走完整新线。
- 新子字段逐项恢复；损坏的新增引文数组或几何元数据不会抛错或清空原案件。
- 微信仍是 `stillwater-chat:v1`，旧消息、独立草稿、未读与滚动沿用原保存。
- 案件先保存事件队列，微信幂等写入并保存后才回执。刷新跨过两份存档的写入间隙不会重复发 15 条消息。
- 固定剧情保留；新账号自由本地回复仍受聊天条数上限约束，不能无限堆积。
- 案件目标与旧目标合并，最多三条调查方向。第一次试玩发现的“新目标覆盖客房入口”已修复。
- 关闭广告设置继续有效。单纯浏览不会为了初始化故事便产生案件进度。原 25 组广告、W3-02 和对应原图片不变。
- A–F 六接头、90° 旋转、互惠线路、AUTO-WRITE 隔离、MANUAL、保存、03:17 原始帧、锁原件条件不变。
- 三种 ending ID 不变，原强行归类／自动结案／保留未核实的路径接回原逻辑；真结局仍要求隔离、保存、黑空间完成与锁定。
- 未来章节直接打开时不展示新增来源、鬼脸或三层年代摘要。

## AI 与服务边界

原七位日常联系人的 AI 传输、同意设置、人物 Prompt、独立记忆和 Cloudflare Worker 没有改动。没有新增后台收费请求，也未读取或要求任何密钥。

**王楚人新账号目前使用固定剧情和本地回复，不是新增的在线 AI 人物。** 界面明确显示“剧情对话与本地回复”。现有已部署 Worker 只允许七位日常联系人，本次没有擅自登录 Cloudflare，也没有伪装成 GGbond 调用它。若以后希望给此账号加入在线闲聊，需要单独扩展后端角色白名单并部署；它的关键剧情仍必须由本地脚本控制。
