# V2.12 / W3-02 酒店宣传资料与影像来源核对

基线为已发布的 `a52e004`（4.11.0）。本轮新增独立的酒店宣传资料线，不替换普通广告、C1–C9、配线谜题或结局。发布版本为 4.12.0。

## 玩家会遇到什么

| 位置与条件 | 展示内容 | 点击结果 |
| --- | --- | --- |
| 论坛：打开兼职帖，或读过两篇不同的普通帖子 | 侧栏「本地资料存档 · 赞助展示」。首次是正常的 2006 宣传扫描件 | 打开宣传资料查看器，不发放案件线索，也不跳过招聘 |
| 招聘：岗位列表下方 | 「档案整理样张 / 非招聘岗位」 | 可比较扫描件与清理后的样张；两者都保留 STAFF ONLY，不提前出现 317 |
| 酒店相册、历史页 | 2006 原始宣传页 | 可放大、翻到照片背面，核对 W3-02 / 2006.09 |
| `night.started` 后的镜像目录 | 「旧资料更新」，中央门牌变成 317 | 查看器开放原版、同步版和预览版，始终保留 2006 原件 |
| 查看通道监控后 | 一次可关闭的「您刚才查看的资料」提醒 | 预览中门牌被覆盖，可出现远处的人影；切到原版后消失。关闭后有一句原件存放位置说明 |
| B-3：按原玩法接通录像，隔离 AUTO-WRITE、切换 MANUAL、保存配置，并恢复最后一帧 | 正式「影像来源核对」面板 | 选择可信的最早照片，再点击 2006 / 2026 对照图中被改写的门牌 |
| 核对成功 | 保留正确来源，出现「继续检查未归档画面」 | 才能进入原有纯黑章节；可选的 650ms 模糊人影只出现一次 |
| 纯黑章节的影像碎片 | 边缘残留 `W3-02 / ... ORIGINAL`，复核后变成 `NO INDEX` | 不增加弹窗、广告轮播、分类选项或新密码 |

普通广告仍由原来的随机池控制。新宣传资料全部是剧情节点下的内嵌展示，只有玩家点击才开查看器，不会自动抢焦点，也不会遮挡帖子或设备按钮。微信界面不显示这条新宣传资料，原有右下角生活广告继续运行。

## 新谜题的实际判定

1. 先满足原 B-3 的有效接线、最后一帧、MANUAL、隔离与保存条件。
2. 在三张图片中选择 **W3-02 / 2006 原始宣传页**。选择同步版或系统临时预览会失败，显示文档中的日期反馈。
3. 在并排的原版 / 同步版照片中点击 **中间门牌**。左门牌、右门牌及灯具都不会通过。
4. 确认原图为 `316 / STAFF ONLY / 318`，同步图为 `316 / 317 / 318`，保存正式核对结果，才开放未归档画面入口。

照片上的热点可以点按、Tab 聚焦后按 Enter，也有同名的普通按钮。触屏热点至少 44×44px，手机按单列显示对照图。原件可以在面板内重新打开，放大查看日期和门牌。完全不点击早期广告也能完成这一步。

原来的锁定仍要等待纯黑章节完成。六个接头、90° 旋转、A 至 F 的连通判定、AUTO-WRITE、MANUAL、保存、撤销与原有三种结局 ID 均保留。新广告不是一个密码输入框，也不会凭点击次数自动过关。

## 存档与设置

- 正式进度仍使用 `stillwater-case:v2`、schema 2。新增的 `promo` 字段保存来源选择、所指出的位置、核对完成与一次性异常是否已处理。
- 正式核对只由 `case-state.js` 验证；展示层不直接修改 `void`、线索或结局。查看照片、放大和翻面只更新宣传资料的观看记录。
- `stillwater-hotel-promo:v1` 单独保存普通帖子浏览、查看过的版本、提醒关闭状态和少量预览次数；不写进原广告收藏存档。
- 已在纯黑章节中、已锁定原件或已有结局的旧存档迁移后可继续，新增门槛不把老玩家送回 B-3。停在 B-3、尚未进入纯黑章节的旧存档会得到可补查原件的核对面板。
- 选择原件后刷新或切换语言仍可继续第二步；核对完成后重接线路不会清掉结果，但原来的有效接线与保存条件仍然要满足。
- 无声不影响判定。新增的短暂人影遵循 `skipScares`、减少动态效果和页面可见性；音效复用现有音量和声音开关。核对成功不会擅自开启声音或鬼脸。
- 确认重新开始游戏时同步清除新宣传线的观看记录与正式核对状态，原广告收藏仍沿用原来的规则。

## 新资产与来源

新增 `assets/hotel-promo-v1/corridor-base.png`，是本轮新建的虚构生成场景，不是现实酒店的历史照片。没有覆盖旧图。生成原稿仍保留在原始生成目录，网页底图的 SHA-256 见 `credits.json`。

三个版本使用同一张 PNG，并由 `hotel-promo.js` 叠加准确的 SVG 门牌、留档日期、预览人影及纸张效果。同步版不更换墙面、门、镜头或整套构图。预览版另有一处灯光覆盖。扫描前后样张只改变清理效果，文字保持一致。异常人影由 SVG / CSS 绘制，没有另找真实人物照片。

素材记录：[来源说明](../assets/hotel-promo-v1/SOURCES.md)、[底图摘要及版本坐标](../assets/hotel-promo-v1/credits.json)。查看器的「图片详情」、游戏图片来源页和开场素材说明均提供了相应说明。

附件给出的中英文广告、背面文字、系统提示及核对反馈均落实在 `hotel-promo-data.js`，没有另写夸张恐怖旁白。

## 可复现的试玩路径

1. 新开浏览器上下文，进入微信，沿原分享卡片打开论坛；也可直接从论坛兼职帖开始。
2. 打开侧栏旧宣传照，放大看三扇门，翻到背面看 W3-02 和 2006.09。关闭查看器，原样进入招聘岗位与工作样本。
3. 按原路径查 R-4829、318、住客留言、317 服务区、维修单、夜审、修订、停业通知和 Mara 草稿，完成 C1–C9 及证据核对。
4. 同步目录后，检查变成 317 的宣传照片；回看房间与留言，再进监控。打开一次更新提醒，切回 2006 原版，确认人影和门牌不属于同一版原件。
5. 按旧规则确认相邻机位、进入维修通道、挪推车、开柜、通电，再进入 B-3。恢复最后一帧，接好六个接头，隔离 AUTO-WRITE、切 MANUAL 并保存。
6. 在来源核对中故意选择同步版、再选原版但点左侧，确认都会失败且接线不丢失。通过「查看原始宣传资料」补查。最后选择原版并点中间门牌。
7. 进入纯黑章节，照旧完成辨门、拼图和四项分类，返回 B-3。锁定原件，选择保留原件并退出夜班，出现 GAME OVER。
8. 分别用英文、手机触屏、键盘、静音、跳过突脸、减少动态效果重复关键步骤；用已进入纯黑章节和已结束的旧存档检查直达与恢复。

自动验证结果与页面采样见同目录 `v2.12/` 的记录。页面截图只表示所采样的状态，不表示每个旧存档都逐帧截图。
